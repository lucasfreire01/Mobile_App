# Vínculo de gateways com AWS, Google Cloud e Oracle Cloud

Os três adaptadores operam pelo cadastro administrativo `POST /api/v1/gateways/attach`, com `providerId`, `name`, `reference` e `sshHostKeyFingerprint`. Usar a impressão digital confirmada por um canal de administração confiável. A exclusão remove o vínculo local. O operador administra o recurso remoto e instala o perfil ou configura o peer IPsec antes de cadastrar. O provedor padrão para novos gateways gerenciados continua definido por `VPN_PROVIDER`.

| Provedor | Configuração no backend | Vínculo |
| --- | --- | --- |
| `aws_client_vpn` | AWS CLI v2 autenticada, `AWS_CLIENT_VPN_ENDPOINT_ID`, `AWS_CLIENT_VPN_REGION` e permissão `ec2:DescribeClientVpnConnections`. | Certificado exclusivo já instalado no Browan. Usar o `CommonName` exato como referência e omitir IP. O adaptador exige uma única sessão ativa no endpoint e valida o IP na allowlist SSH. [AWS CLI](https://docs.aws.amazon.com/cli/latest/reference/ec2/describe-client-vpn-connections.html) |
| `google_cloud_vpn` | Google Cloud CLI autenticada, `GOOGLE_CLOUD_VPN_PROJECT`, `GOOGLE_CLOUD_VPN_REGION`, `GOOGLE_CLOUD_VPN_TUNNEL` e permissão `compute.vpnTunnels.get`. | O túnel de site a site precisa estar em `ESTABLISHED` ao vincular. Informar o IP de gerenciamento roteável e uma referência de inventário exclusiva para o Browan. [Status da Cloud VPN](https://docs.cloud.google.com/network-connectivity/docs/vpn/how-to/checking-vpn-status) |
| `oci_site_to_site_vpn` | OCI CLI autenticada, `OCI_VPN_REGION`, `OCI_VPN_CONNECTION_ID` e `OCI_VPN_TUNNEL_ID`. A identidade do serviço precisa consultar o túnel de laboratório. | O túnel de site a site precisa estar em `UP` ao vincular. Informar o IP de gerenciamento roteável e uma referência de inventário exclusiva para o Browan. [OCI CLI](https://docs.oracle.com/en-us/iaas/tools/oci-cli/latest/oci_cli_docs/cmdref/network/ip-sec-tunnel/get.html) |

Em Google Cloud e OCI, cada adaptador consulta um túnel fixo na instalação. Vários gateways podem usar esse túnel. A referência de inventário identifica o dispositivo no SagaNexus. Depois do vínculo, a sonda usa SSH para verificar o gateway pelo IP configurado e pela chave de host. O estado do túnel, por si só, não comprova quais dispositivos da LAN estão disponíveis.

Para o canário, incluir somente o CIDR de gerenciamento necessário em `GATEWAY_SSH_ALLOWED_CIDRS`, conferir a rota a partir do worker e confirmar SSH com a chave de host esperada. Na AWS, usar o backend e o Browan como clientes do mesmo endpoint de laboratório, com rota e autorização de tráfego entre os clientes. Reiniciar o Browan e repetir a prova. Na AWS, confirmar resolução da sessão nova. Em Google Cloud e OCI, confirmar retorno da rota e do acesso pelo IP fixo. Depois do teste, remover o vínculo local e usar o plano de rollback do laboratório para qualquer mudança externa. [Tráfego entre clientes AWS](https://docs.aws.amazon.com/vpn/latest/clientvpn-admin/how-it-works.html) · [Canário AWS](AWS-Client-VPN-canario.md)
